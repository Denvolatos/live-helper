# 🗺️ 路线图

> 这是方向，不是承诺：每一步开工前会再确认范围，实测结果会改变计划。写下这份是为了记录我们打算怎么一步步做。

## 现状

- **v1.x（Windows）**：Python + customtkinter 界面，streamlink 取流，PotPlayer 播放，自己做的弹幕悬浮层。最新版见 [Releases](../../releases)。

## 两条线并行

| 线 | 做什么 | 原则 |
|---|---|---|
| **v1.x 老线** | 修 bug、改后端逻辑、小功能 | 大块界面功能不放这里（v2.0 界面是网页技术，旧界面代码用不上，会白做） |
| **v2.0 新线** | 换引擎，慢慢打磨 | 在 `v2` 分支做，做好之前不影响任何发布；预发布不会被应用内更新推给用户 |

## 版本规划

| 版本 | 内容 | 状态 |
|---|---|---|
| **v2.0** | **换引擎**：后端仍是 Python（取流、画质、续播、弹幕协议、更新检查沿用 1.x），界面换成网页技术（pywebview + HTML/CSS）。目标：拖动流畅、界面更精致。结构按"两个系统通用"设计，平台相关的部分单独一层 | 已选定方向，界面小样已试过，未开工 |
| **v3.0** | **内置播放器 + 弹幕**：在界面里直接播放（网页里用 flv.js / hls.js 之类播直播流），弹幕画在视频上或放在旁边的侧栏，类似「纯粹直播」。弹幕在网页里画，不再依赖读取别的程序的窗口，Mac 的弹幕问题也一并解决 | 未开工；**开工前先做最小实验**（见下） |
| **v4.0 及以后** | 视功能再定，不绑定顺序 | 待定 |
| 云端备份 | 搁置。较轻的办法是导出/导入备份文件，或让用户选一个自己的同步文件夹；真正的云端账号服务维护负担大，以后再说 | 搁置 |

## v3.0 开工前要验证的风险（目前都没有测过）

1. 虎牙、斗鱼的直播流在网页里能不能播：它们对请求来源有限制，可能要在本地起一个小转发程序补请求头。
2. 画质、编码、延迟：不同房间的流格式不同，要实测。
3. 播放流畅度和 PotPlayer 相比如何：没有数据。

第一步是最小实验：只在网页里播一个真实的流，看能不能播、卡不卡、延迟多大，再定 v3.0 的范围。

## macOS 版

- 建在 v2.0 之上，界面一份代码两系统通用；播放器用 mpv，不签名，首版不做弹幕（等 v3.0 的网页弹幕）。
- 打包 `.app` / `.dmg` 必须在 Mac 上完成。
